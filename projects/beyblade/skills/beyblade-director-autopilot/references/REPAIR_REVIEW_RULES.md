# Repair evidence and reference roles

Apply to Beyblade clip review and repair. Keep current take IDs, exact timings, uploads and pending work in the project's repair ledger; reconcile its snapshot against live state before mutation. A historical assistant completion message is not stronger evidence than the corresponding receipt or a later user correction.

## Identity and motion

Use original canonical character/prop pixels in repairs. A previously generated board may contain the defect being repaired. Preserve approved composition when requested, but do not use that board alone to establish face, age, proportions, hand anatomy or mechanism design. Recheck the whole result, since a background repair can change identity.

Give every independent prop a support and motion state at entry, during action and at exit. An extracted rack has no physical connection to a launcher: it stays grounded if untouched and moves only with its own hand/support. Count checks alone cannot rule out floating, dangling or inherited motion. A moving launcher is one rigid head-plus-grip assembly; extraction moves only the thin rack through its guide.

A concealed object remains part of world state without being an exposed visual subject. Continue the preceding bundle/pocket state; do not reopen it merely to show an attached canonical top. Remove genuinely unused visual references and their consuming definitions/shot entries together, while preserving the object's state in the authoring record. Recheck the retained storyboard against the changed state.

## References and compiler boundaries

For each attachment record its purpose: visible identity/design, composition, current physical state, literal frame constraint or voice. Multiple views of one character do not authorize multiple bodies. A name spoken in dialogue is not a visual attachment request.

Budget the actual simultaneous canonical images, requested storyboard and selected predecessor frame against the current provider/resolver limit. Deduplicate/remove unused inputs first; never discard a required identity to make room. Do not assume a universal image count. Keep required voice references separate from unused visual assets.

After removing/adding a reference, check every Subject definition, retention entry, shot usage and required/visible-asset list, then resolve actual Picture/Audio labels through the runtime. Do not renumber from the asset-library order or leave references to removed subjects.

An omission warning can be historical. A readable board, reference checkbox or stale=false does not establish inclusion in the request. Use exact-job attachment evidence when available; otherwise report payload inclusion unknown. Reducing the asset count alone does not prove the board is now attached.

Planning text and final H3 output are distinct layers. Use the current importer/compiler schema: normalized ShotPlanningPrompt and StoryboardReferencePrompt reject attachment labels and final H3 wrapper sections. The H3 packager owns resolved labels. Some package adapters separately accept complete H3 text; verify that route before using it, rather than sending final H3 through a planning-only field.

## Acceptance and status

Record separate results for source/text, persistence readback, attachment payload, board pixels, rendered motion, dialogue words/timing, audible timbre and lip-sync. Use pass, fail, unknown or not required accurately. Current saved text may postdate the reviewed take; never claim it caused that take without job provenance.

Use consecutive frames for causal motion and listen for voice identity. Whole-clip and cropped ASR can corroborate a repeated line, but unstable recognition over silent/music passages is not proof of specific random speech. A silent fixture verifies mapping only, never real timbre.

User correction revokes the affected acceptance. Keep one current record per segment with source/asset hashes, exact take evidence, latest authorized intent, superseded record links and unresolved checks. Store abandoned timings and theories in history; do not append them as parallel active instructions. Preserve no-generation and other scoped user choices.

For single-shot landscape repair images, record their actual role as runtime composition references. Director-package boards still follow the selected contract's aspect and panel layout unless an explicit supported override is recorded. Do not retrofit acceptance merely because a runtime upload succeeded. Inspect actual decoded resolution; a requested 4K size or filename is not a delivered 4K image.
