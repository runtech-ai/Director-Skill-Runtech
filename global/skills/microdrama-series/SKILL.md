# Microdrama series

Produce a series, not disconnected short films. Read [the series contract](references/series-contract.md) before packaging. Use the bundled [Director Pack](../director-pack-skills/SKILL.md) skill for each episode; its selected authoring profile, child schemas, H3 validation and storyboard preflight remain authoritative. For this microdrama workflow, select **Director v9** explicitly, consistent with the plugin's v9 default. Record `authoring_profile: v9` in direction.md and README.txt using the contract's supported profile mechanism; do not change the shared plugin selector. Later explicit user choices take precedence. The series envelope never changes `movie-director-result` / `3.1-shotplan-only`.

## Persistent microdrama directing preferences

These are the user's microdrama defaults, saved 2026-10-10. Apply them on future microdrama requests unless explicitly overridden.

- **Preserve explicit episode divisions and deliberately supplied source scene/story units; an episode may contain multiple directed scenes.** For a summary-only input, develop episode boundaries from dramatic turns, not paragraph breaks. A summary paragraph is not automatically an episode. Preserve the source-to-episode mapping in the series bible. Split that episode into cinematic scenes when location, time, action or dramatic progression requires it, each with v9-compliant segments and micro-shots. Do not impose a one-directed-scene limit, and do not automatically make each directed scene or segment a separate episode.
- **Fast, dramatic, story-driven pacing.** Open on an active conflict, urgent objective or revealing line. Every shot must advance action, stakes, emotional pressure, information or a consequential reaction. Avoid leisurely establishing shots, filler montage, repeated exposition and empty pauses. Allow a brief charged hold only when it strengthens a turn; fast pacing must preserve comprehension and believable performance.
- **Dialogue or narration carries the story.** Use purposeful dialogue and/or motivated narration to make the conflict, stakes and turns clear, supported by visible action. Do not repeat what the picture already establishes. Preserve supplied dialogue and language; when adapting a locked source, propose necessary additions instead of silently inventing lines. Time speech with v9 occupancy rules and natural delivery; split segments instead of rushing speech. Narration belongs in the contract's supported voiceover/audio representation, never in picture-only action prose.
- **Every episode ends on a cliffhanger**, including a final unresolved threat, revelation, reversal, interrupted choice or consequential question. Build and seed it within the episode. Pay off the series' central dramatic question in the finale while leaving a meaningful forward hook. Do not manufacture an unexplained continuity break to create suspense.
- **Match continuity across segments and episode boundaries.** Carry exact end states into the next opening: pose, position, eyeline, screen direction, action phase, wardrobe, injuries, prop ownership, environment, light, time and character knowledge. Use MATCH_CONTINUITY where the supported schema and physical continuation warrant it; respect explicit HARD_CUT boundaries and never carry previous-frame references across them. Document motivated time/location changes and establish the new state clearly.
- **Appropriate non-diegetic music.** Plan a restrained dramatic score tied to the scene's emotional arc, escalation and cliffhanger. Specify cue entrances, transitions, intensity and ending/bridge; preserve musical continuity across continuing segments and episode boundaries where appropriate. Duck beneath dialogue/narration, reserve silence for deliberate dramatic effect and distinguish score from in-world sound. Use supported H3 music/soundscape fields, not picture-only prose.

## Develop the series

Accept a premise, plot or existing script. Preserve supplied events, dialogue, characters, language and cultural setting. Establish episode count, duration, visual style, aspect ratio and audience from the request. When unspecified, propose a clearly labelled starting brief of six 60–90 second episodes in 9:16; these are creative defaults, not schema limits. Resolve consequential uncertainties while developing independent material.

Write a compact series bible: central dramatic question, protagonist want and need, opposing force, stakes, escalation, ending and reveal schedule. Give each episode an opening hook, immediate objective, escalating obstruction, a consequential turn and a cliffhanger that drives the next episode. The finale pays off the central question. Avoid repeating the previous cliffhanger as an entire episode. Count runtime from directed segments, including dialogue occupancy, rather than word count alone.

Maintain a continuity ledger per episode: time, place, who knows what, relationships, injuries, wardrobe variants, prop possession, damage and location state. Seed later reveals before payoff. Carry explicit episode-end state into the next episode's opening; distinguish an editorial cut from physical continuity.

## Establish canonical assets

Extract a series-wide asset registry with stable @handles before directing episodes. Include every visible character, wardrobe variant, creature, important prop, vehicle and environment. Record identity, description, immutable features, allowed variants, scale and episode appearances. Never use fuzzy character-name matching to assign references.

Use the available built-in image generation skill/tool to generate real images. A character sheet should establish face identity, full-body proportions and costume with useful front/side/back views; add a separate variant when continuity requires a different outfit. Props need readable scale, material and relevant operational states. Environments need a useful establishing view, layout, entrances and fixed spatial landmarks. Respect existing canonical references and supply them during edits and derivative image generation. Inspect generated pixels before acceptance. Do not regenerate the same canonical identity independently for each episode.

Keep approved master images in the working series asset library. Copy the relevant identical bytes into each episode's self-contained `assets/` tree and declare them in its existing `asset-manifest.json`. New projects must not retain unrelated `assetLibraryIds` from an exported project. Do not substitute prompt text, URLs, empty files or placeholders for required images.

## Import-complete assets and segment controls

A package upload must populate the tool's actual character/asset and location records, with usable reference images and correct scene/segment bindings; importing only storyboards is incomplete. Include every required character and wardrobe variant, prop, creature, vehicle and location with stable handles, supported importer declarations, real image bytes and episode-local paths. Inspect the current importer/schema and use `runtech-movie-mcp` when operating the tool; never invent fields or assume files alone create library records. Validate reference closure and asset/location creation through the available inspect/import response. When import is requested, read back the resulting library, locations and segment bindings. If the importer cannot create a required record, use supported tool operations within the authorized import scope; otherwise report the specific importer limitation rather than claiming upload completeness. Do not upload solely to test a package without upload authorization.

Set storyboard and keyframe controls explicitly per segment using supported importer fields or supported post-import settings, so the user does not have to enable them manually. Enable storyboard use on segments whose authored board is supplied and intended as a reference. Choose keyframe enablement and generation mode from the shot plan: enable applicable first/end frames for segments requiring image-conditioned starts, controlled endpoints or match-continuity handoffs. Supply the required real frame assets or supported generation configuration. Keep a multi-panel board distinct from a single initial/end keyframe; never pass the whole board as a keyframe. Respect HARD_CUT boundaries, active-take previous-frame authority, and each H3 mode's valid reference combinations. Record each segment's storyboard setting, keyframe setting, frame roles and reason in the handoff evidence. Verify effective settings after import when authorized; if a required flag is not supported by the ZIP importer, disclose it and apply the supported tool setting instead of silently leaving it off. Enabling controls does not authorize running video generation.

## Direct and render episodes

Write one `movie.movie` source per episode using the existing MovieScript DSL skill. Produce a complete Director package per episode through the installed Director Pack skill. It owns scene allocation, micro-shots, compiled H3 prompt envelopes, timing, canonical reference bindings and validation. Use scene and segment IDs valid under that schema; IDs may repeat between episodes because the importer scopes them to distinct scripts.

Render one storyboard image per segment from that segment's authored shots, using canonical images. Preserve the Director panel count, inverse board aspect ratio, stack layout and pixel-review gates. Embed boards inside the episode package using paths supported by the existing importer, so the final series ZIP needs no separate storyboard upload. Keep filenames equal to segment IDs. Validate compiled H3 prompts and complete reference closure. A storyboard is a shot reference sheet, not an H3 initial frame unless the selected generation mode explicitly requires one.
